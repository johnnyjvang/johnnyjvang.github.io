TurtleBot3 ArUco Multi-Robot Tracking

View Full Project on GitHub

A ROS 2 (Jazzy) computer vision and mobile robotics project focused on robot-to-robot tracking using OpenCV ArUco markers, RGB camera input, LiDAR safety checks, recovery behavior, and VFH-style obstacle-aware following.

Project Overview

This project was built as a perception-to-control pipeline for following a moving TurtleBot3 target robot in Gazebo. The follower robot uses an RGB camera to detect ArUco markers mounted on the target robot, estimates marker position, and converts that information into velocity commands.

The ArUco tracking work progressed from basic single-marker detection to multi-tag tracking, smoother control, LiDAR-based safety behavior, recovery backup logic, and VFH-style obstacle avoidance.

Development Progression

Purpose: Detects ArUco markers from camera input

Why It Was Added: Validated that the TurtleBot3 camera could see and identify ArUco tags in Gazebo

aruco_front_detector_only

Purpose: Tests ArUco detection with marker-facing filtering

Why It Was Added: Added to test whether backside marker detections could be rejected using marker orientation

aruco_pose_tracker

Purpose: Estimates marker pose and publishes target position

Why It Was Added: Converted raw marker detection into distance and offset values that a robot controller could use

aruco_follower

Purpose: Follows target robot using pose-based control

Why It Was Added: Closed the loop by converting ArUco pose estimates into forward and turning velocity commands

aruco_multi_detector

Purpose: Detects multiple ArUco tags and publishes structured detection data

Why It Was Added: Expanded tracking from one visible tag to multiple tags placed around the target robot

aruco_multi_follower

Purpose: Follows the target robot using multi-tag priority logic

Why It Was Added: Improved tracking continuity when the target robot rotated and exposed different marker sides

aruco_upgraded_multi_follower

Purpose: Adds EMA smoothing, proportional control, LiDAR safety, avoidance, and recovery backup

Why It Was Added: Improved motion smoothness and added obstacle safety after the robot showed rough movement near poles

aruco_vfh_follower

Purpose: Uses VFH-style LiDAR sector steering for smoother obstacle-aware following

Why It Was Added: Replaced simple left/right avoidance with sector-based steering to reduce zig-zag behavior

What Was Built

  • ROS 2 camera subscriber for TurtleBot3 RGB image input
  • OpenCV ArUco detector for marker ID detection
  • Pose estimation using marker size and camera calibration approximation
  • Single-marker follower for basic visual robot tracking
  • Multi-marker detector for front, back, left, and right target tags
  • Multi-tag follower using marker priority logic
  • Backside marker filtering experiment using ArUco rotation vectors
  • EMA-smoothed follower to reduce noisy camera-control behavior
  • LiDAR emergency stop and recovery backup behavior
  • VFH-style LiDAR sector steering for smoother obstacle-aware following

Single ArUco Follower

The first working follower used one ArUco marker and a simple perception-to-control pipeline. The camera detected the marker, estimated its pose, and the follower used distance and horizontal offset to command the robot.

Perception to Control Pipeline

Camera → ArUco Detection → Pose Estimation → Pose Topic → Follower Controller → cmd_vel

Following Behavior

  • Moves forward when the target is far
  • Rotates toward the target when off-center
  • Stops at a defined distance threshold
  • Stops automatically if the marker is lost

Multi-ArUco Tracking

The next step was to move from one marker to multiple markers. This allowed the target robot to be tracked from different viewing angles instead of only when one marker was visible.

Four markers were assigned to the target robot: 

0 = back
1 = front
2 = left
3 = right

Multi-Tag Selection Logic

  • Detects all visible markers in the camera frame
  • Publishes structured detection data with marker ID, side, distance, and image offset
  • Prioritizes the back tag first, then side tags, then front tag
  • Improves tracking when the target robot rotates

Upgraded Multi-Follower

After basic multi-tag following worked, the follower was upgraded to improve motion stability and safety. The original multi-follower reacted directly to camera readings, which could create rough movement when marker estimates jumped between frames.

The upgraded version added smoothing, proportional control, LiDAR emergency stop, simple obstacle avoidance, and recovery backup behavior.

Control Improvements

  • EMA smoothing reduces jitter from noisy ArUco distance and alignment readings
  • Proportional control scales forward and turning speed based on tracking error
  • LiDAR emergency stop prevents the robot from continuing forward into close obstacles
  • Recovery backup lets the robot reverse and turn away when it gets too close
  • Marker-facing filtering helps reduce false detections from the backside of tags

VFH ArUco Follower

The VFH follower was added after simple left/right avoidance caused rough movement and zig-zagging near obstacles. Instead of only choosing left or right, the VFH-style follower divides the LiDAR scan into angle sectors and chooses a safer steering direction closest to the ArUco target direction.

VFH Pipeline

LiDAR Scan → Sector Generation → Clearance Check → Best Heading Selection → cmd_vel

VFH Improvements

  • Uses multiple LiDAR sectors instead of only left/right decisions
  • Selects the open sector closest to the target direction
  • Creates smoother steering around poles and walls
  • Reduces oscillation compared to simple avoidance
  • Keeps emergency stop and recovery backup behavior as safety layers

Key Engineering Insights

  • Camera-based pose estimates can be noisy, so smoothing is important before control
  • Single-marker tracking works but loses reliability when the target rotates
  • Multi-tag tracking improves visibility around the robot body
  • Vision-based following needs LiDAR safety checks to avoid collisions
  • Simple left/right avoidance can create zig-zagging near obstacles
  • VFH-style sector steering provides smoother obstacle-aware following

Future Improvements

  • Add a formal state machine for following, avoiding, recovery, and lost-target modes
  • Improve marker-facing filtering for stronger backside rejection
  • Tune VFH parameters across more obstacle layouts
  • Add AprilTag support for comparison against ArUco tracking
  • Test the full tracking workflow on physical TurtleBot3 hardware
