A ROS 2 (Jazzy) mobile robotics project focused on TurtleBot3 navigation, autonomous exploration, goal execution, patrol behavior, and map-based validation in Gazebo.

Project Overview

This project was built as a hands-on testbed for learning and validating applied mobile robotics workflows using TurtleBot3, ROS 2, Nav2, SLAM, and Gazebo.

The Nav2 and SLAM portion focuses on progressively building navigation behavior from simple goal execution to autonomous exploration. Each node was added to test a specific capability before moving toward more complex exploration behavior.

Navigation Progression

The project started with simple one-goal navigation so that Nav2 communication, map usage, localization, and robot movement could be validated. After that, return behavior, goal-list execution, random safe exploration, and timer-based patrol exploration were added step by step.

single_goal_nav

Purpose: Sends one Nav2 goal to the robot

Why It Was Added: Validated the basic Nav2 action client workflow and confirmed the robot could move to a target pose

single_goal_return

Purpose: Sends a goal and returns from that goal

Why It Was Added: Tested repeatable navigation by sending the robot out and then back to its starting region

goal_from_list

Purpose: Runs navigation goals from a predefined list

Why It Was Added: Expanded from one goal to multiple known waypoints for route-following experiments

random_safe_goal_explorer

Purpose: Selects safe random goals for exploration testing

Why It Was Added: Added autonomous goal sampling while avoiding obviously unsafe or unreachable map regions

timer_based_patrol_explorer

Purpose: Runs patrol and exploration behavior for a timed session

Why It Was Added: Added structured exploration by sending goals at intervals and saving output maps for review

What Was Built

  • ROS 2 Python nodes for Nav2 goal navigation
  • Single-goal navigation for basic action client testing
  • Return navigation behavior to validate repeated movement
  • Goal-list navigation for waypoint-based route execution
  • Random safe-goal exploration for autonomous movement testing
  • Timer-based patrol exploration with saved map output
  • Custom TurtleBot3 Gazebo world launch support
  • Map logging and visual validation of robot exploration behavior

Random Safe Goal Explorer

The random safe goal explorer was added after basic Nav2 movement was working. Instead of manually choosing every goal, this node samples random candidate goals and checks whether they are usable before sending them to Nav2.

This helped test whether the robot could keep moving through the map without constantly requiring manually selected target poses.

Random Exploration Behavior

  • Samples random candidate goals from the map
  • Avoids invalid or unsafe goal areas
  • Uses Nav2 to plan and execute paths
  • Tracks visited locations for visual review

Timer-Based Patrol Explorer

The timer-based patrol explorer was added to make exploration more structured. Instead of waiting for one goal to fully define the behavior, the node dispatches goals at timed intervals so the robot continues moving and patrolling during a test session.

This made the exploration behavior easier to repeat, observe, and compare across simulation runs.

Patrol Exploration Behavior

  • Dispatches navigation goals at timed intervals
  • Uses Nav2 to plan and execute paths
  • Tracks completed goal locations
  • Saves a map visualization of visited goals

System Pipeline

Map / SLAM Output → Nav2 Stack → Goal Selection Node → Navigation Action Client → Robot Motion → Map Result Logging

Key Engineering Insights

  • Nav2 behavior should be validated with simple goals before adding exploration logic
  • Return behavior is useful for testing repeatability and localization stability
  • Goal-list navigation helps bridge manual navigation and autonomous exploration
  • Random exploration requires safety checks before sending goals to Nav2
  • Timer-based patrol behavior makes exploration testing easier to repeat and compare
  • Saved map outputs make it easier to validate coverage and path behavior after a run

Future Improvements

  • Add stronger frontier-based exploration
  • Improve automatic goal validation using costmap data
  • Add more detailed exploration metrics
  • Compare random exploration against timer-based patrol behavior
  • Test the navigation workflow on physical TurtleBot3 hardware
